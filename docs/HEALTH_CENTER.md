# 状态

管理台侧栏的 **状态**（`/#/health`）集中展示当前问题、判断证据、关联节点和站点，以及近期恢复记录。页面沿用现有管理台的浅色/深色主题，支持中英文和移动端。

## 使用方式

- 默认显示严重、需关注和待确认的检查，按严重程度优先排序；可按状态、检查范围、节点、站点和名称筛选。
- 点击检查项查看影响说明、首次发现时间、来源数据时间和证据，再进入对应节点、站点、监测或备份设置处理。
- “恢复记录”区分后续检查通过和对象被停用/移除，后者不计为故障恢复。总览数字始终针对全部检查，不随列表筛选变化。
- 页面每 15 秒读取最新结果。“刷新结果”只读取保存的结果，不启动探测或运维任务。

## 第一版检查范围

| 检查 | 判断依据与边界 |
| --- | --- |
| 节点心跳 | 运行节点 90 秒内心跳有效；超时为严重。未上报或时间超前超过 30 秒为待确认；暂停、待注册、撤销等非运行节点停止检查。 |
| 节点配置一致性 | 对比期望版本与节点确认版本，落后或节点报告错误为需关注；缺少近期心跳或已分配站点却无期望配置为待确认。 |
| 站点 IPv4 / IPv6 可用性 | 使用已发布站点配置和现有节点/站点探测的 DNS 可用资格，沿用现有探测滞回，不新增外部探测。探测须在 3 分钟内且不早于本次发布，心跳须在 90 秒内；数据缺失不视为探测成功。全部运行节点探测失败或没有可服务节点为严重，部分异常为需关注，无法确认任何健康路径且存在未知结果时为待确认。未启用 IPv6 的站点停止该项检查。 |
| 发布任务 | 展示当前最近一次发布结果；失败、部分成功、回滚、超过截止时间或活动任务 10 分钟未更新为需关注。正常进行中的任务显示进度说明。 |
| 站点证书 | 优先检查已发布服务证书：已过期或 7 天内到期为严重，进入 30 天续期窗口为需关注。缺少已发布证书有效期为待确认。单独展示最新签发证书的有效期，签发成功不等同于已发布；近期签发/续期任务失败或超时也会提示。 |
| 备份时效 | 复用备份健康状态：默认有效期为 26 小时加调度随机延迟，执行超过 6 小时视为卡住；支持已有备份健康配置覆盖。未配置备份单独标记为未启用。 |
| 恢复验证 | 复用隔离恢复验证结果，默认 7 天内应有成功记录；未验证、过期或最新验证失败为需关注，并展示已验证快照的时间。在线恢复未启用时停止检查。 |
| 节点与分批升级 | 最近节点升级失败或超过任务期限、分批升级暂停为需关注；运行中的批次超过 3 分钟没有进度更新为待确认。取消的批次停止检查。 |
| 健康协调器 | 展示最近一轮健康探测和 DNS 对账结果；有错误或超时为需关注，超过 3 分钟无完成记录为待确认。 |

“正常”表示该项近期证据通过，不代表所有外部依赖或访问路径均已验证。站点检查展示的是控制面的探测视角，未验证公网递归 DNS 缓存或用户端端到端访问。暂停节点不参与运行节点探测统计；主备节点均按已发布分配关系关联。

## 数据与接口

控制面启动 `SystemHealthManager` 后立即采集一次，随后每轮结束等待 30 秒。采集在一个有 10 秒截止时间的 SQLite 只读事务中读取节点、已发布配置、任务、证书有效期及已有探测结果，结合内存中的协调器状态和本地备份状态生成快照。它不调用任务对账、DNS 修改、升级派发或恢复操作，也不读取证书私钥。

`GET /api/system/health` 需要管理员会话，返回 `Cache-Control: no-store`。响应包含：

- `state`：`critical`、`warning`、`unknown`、`healthy` 或 `disabled`。
- `collected_at`、`valid_until`、`stale`：采集时间、90 秒有效期和过期标记。
- `checks`：稳定检查 ID、类别、状态、摘要、影响、关联对象、来源时间、首次发现时间、证据及管理台操作链接。
- `nodes`、`sites`：关联对象 ID 与名称；`recoveries`：有界恢复/停止检查记录。

无快照、采集失败或快照过期都会显式提示待确认；已知严重/告警仍保留。过期的正常检查转为待确认，浏览器在网络中断后也会本地检查有效期。页面刷新不会推进采集时间。`/healthz` 保持原有进程存活语义，不依赖聚合健康结果。

数据库迁移 40 新增单行 `system_health_snapshot` 表，原子保存最新快照和最多 100 条、最近 30 天的记录。连续异常期间严重程度变化不重置首次发现时间；恢复正常才结束该轮问题。删除或停用标记为停止检查。失败的采集不会覆盖上一份快照或制造恢复记录，控制面重启后记录保留。

## 当前边界

第一版提供查看、筛选、证据与处理入口，不新增自动修复、确认/忽略/静默、健康分数、SLA 或独立通知策略；现有备份、探测等模块继续负责各自通知。暂不汇总 ClickHouse/SMTP/Cloudflare 的独立依赖检查、日志队列积压、持续 CPU/磁盘压力和 WireGuard 逐链路诊断。这里的检查记录不是全量监控时序数据库。
