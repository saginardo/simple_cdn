# 智能路由

“监测 > 智能路由”按节点控制是否参与所有站点的边缘调度。它只切换节点现有的 `active` / `draining` 状态，不修改站点分配、发布配置或证书。

## 门控规则

每个节点有一个总开关，并可独立启用评分门控和时间门控。总开关开启时，所有启用的门控都必须放行，节点才可以进入调度：

- 评分门控：低于暂停阈值并达到连续轮数后阻断；达到恢复阈值并达到连续轮数后放行。恢复至少需要连续 3 轮正常拨测，任一轮未达到恢复阈值都会重新计数；人工接管期间的拨测轮次同样计入连击。恢复阈值不能低于暂停阈值，形成滞回区间，避免评分在边界附近反复切换。
- 时间门控：每周重复的时间窗表示允许调度的区间。多个窗口取并集；窗口外阻断。
- 评分和时间门控同时启用时采用 AND 关系。任一门控阻断都会使节点保持 `draining`。

默认策略为：总开关开启、评分门控开启、低于 80 分连续 4 轮暂停、达到 80 分连续 3 轮恢复、时间门控关闭。恢复轮数可配置为 3 到 120 轮。

节点评分算法保持固定：连接成功率占 70%，成功连接的平均延迟占 30%。延迟不超过 100 ms 得满分，100-1000 ms 线性衰减，达到 1000 ms 后为 0 分。页面“节点评分”的正常线仍固定为 80 分；智能路由阈值是每节点独立配置。

## 时间窗

- 时区固定为 `Asia/Shanghai`。
- 星期使用 ISO 编号：`1` 为周一，`7` 为周日。
- 开始时间包含，结束时间不包含。
- 结束时间早于开始时间时，窗口跨到次日。
- 开始和结束时间相同时，表示所选星期全天开放。
- 每个节点最多配置 32 个窗口，配置精度为分钟。

控制面现有健康协调器每 15 秒重新计算时间门控。节点状态切换后，DNS 仍受原有节点健康、站点健康和 DNS TTL 约束。

## 所有权与异常状态

智能路由只恢复由自身暂停的节点。管理员手动暂停、恢复或撤销节点时，会原子关闭该节点的智能路由总开关并清除自动所有权；评分和时间窗配置保留。关闭期间评分门控仍随监测轮次刷新（阻断/恢复双向推进、连续轮次持续累计），但只更新门控结论，不会改动节点状态；重新开启总开关后，控制权交回智能路由，已累计的连续轮次不会被清零——若接管期间评分已恢复，节点不会被再次移出调度。

评分尚未上报或超过 75 秒未更新时，不改变上次评分门控结论。新节点在首次评分前保持放行，由现有节点和站点健康检查继续提供最终 DNS 保护。

评分门控发生阻断或恢复时会发送监测类通知。若评分恢复但时间门控仍阻断，通知会明确节点尚未恢复调度。时间窗切换只记录审计，不发送邮件。配置变化、门控变化和实际节点状态变化都会写入审计日志。

## API

管理员接口：

- `GET /api/monitoring/smart-routing`：返回时区、所有节点策略、当前门控、阻断原因和下一次时间切换。
- `PUT /api/monitoring/nodes/{id}/smart-routing`：完整替换单个节点的智能路由配置。

请求示例：

```json
{
  "enabled": true,
  "score": {
    "enabled": true,
    "pause_below_score": 75,
    "pause_after_rounds": 4,
    "resume_at_score": 85,
    "resume_after_rounds": 3
  },
  "schedule": {
    "enabled": true,
    "windows": [
      {
        "weekdays": [1, 2, 3, 4, 5],
        "start": "08:00",
        "end": "23:00"
      }
    ]
  }
}
```

人工节点状态接口 `POST /api/nodes/{id}/status` 的响应包含 `smart_routing_disabled`，用于提示本次操作是否接管并关闭了智能路由。
